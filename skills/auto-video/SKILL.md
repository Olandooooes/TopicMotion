# 自动视频制作

用户给话题后，使用当前对话模型完成内容与分镜，使用本 Skill 的本地程序完成配音和渲染；不要求另配模型 API，不启动第二个聊天模型或子代理。用户不需要手写脚本或操作时间线。Skill 是在 Codex 中运行的制作流程，不是离开 Codex 后独立生成任意话题的网页服务。

## 从请求到成片

- 从用户指令提取话题、风格、时长。未给的可默认：中文、cartoon、30 秒、横屏 1280×720。已有明确偏好时沿用，不为例行制作反复提问。
- 需要核验事实时先检索权威来源。把资料改写成适合口播的内容，避免无根据统计、虚构引用和把解释性图形称为实测数据。不要把内置 RAG 示例当成任意话题的固定脚本。
- 阅读 [任务格式与风格](references/job-format.md)。按话题编写原创场景 JSON，控制总字数约每秒 3–4 个汉字，为转场和停顿留空间。将生成的任务保存到用户工作目录，输出使用新目录。
- 执行本 Skill 的 `scripts/render.mjs --job /绝对路径/job.json --out /绝对路径/输出目录`。以实际 Skill 文件位置定位脚本，不假定仓库路径。程序首次缺少依赖时用 npm ci 安装已锁定依赖，不需要用户的模型密钥。
- 程序自动合成每句配音，测量实际长度，对齐字幕和场景，生成动画并导出 MP4、封面、脚本、SRT、时间线和报告。若提示文案过长，压缩该场景文案后在新输出目录重试；不要截断口播假装完成。
- 检查实际视频：至少开头、中间、片尾的画面，时长、中文字体、口播是否被切断和字幕遮挡。出错时修复并验证，不能把仅完成文案或预览页面当作成片。
- 返回可播放成片、脚本和输出位置，说明本次风格、实际时长和重要限制。默认只本地制作；用户要发布时再按其授权处理。

## 当前运行边界

当前本地配音适配器已在 macOS 的 `say`（Tingting）验证，需 Node 22.13+ 和可用 Chrome/Remotion 浏览器。其他系统暂不承诺一键配音，应实现当地可用 TTS 适配器后再渲染，不能静默改成无声。

三个内置画面风格是程序化 motion graphics，不是生成式实拍或逐帧角色动画。不把这些尚未实现的能力当作可选项展示。图片或真实镜头若后续加入，需有实际素材来源和相应使用权限。

代码与自制 SVG 适用项目 MIT；Remotion 依其自身许可。系统语音输出只作用户本地试听，不自动纳入开源许可或对外发布。不要提交输出目录、临时配音或用户素材。
